# Music AI Lab Site Design

## 目标

网站以 52 周 roadmap 为内容骨架，而不是把路线、笔记、代码和 Notebook 拆成四个互不
相干的文件列表。用户从阶段或周次进入，先理解当前学习目标，再阅读与它直接相关的笔记、
练习代码和实验结果。

网站只负责呈现仓库内容，不编辑或执行内容。仓库文件仍是唯一数据源，`site/` 只保存
网页实现、静态资源和部署配置。

## 设计原则

### 内容优先

- 屏幕的主要面积交给路线说明、文章正文和源码，不交给装饰性 hero、重复介绍或空卡片。
- 不用巨型标题制造“设计感”。标题建立层级后立即进入有效内容。
- 不把每个文本块都装进卡片。边框、底色和阴影只用于确实独立的学习产物或交互状态。
- 不提供“笔记”“代码”“Notebook”三个仓库级入口，也不把所有文件平铺给用户。

### 有节奏，而不是一味压缩

信息密度分成三个层级：

1. 周次索引、路径、标签和元信息保持紧凑，便于扫描；
2. 学习目标、正文和源码保持舒适行距与行长，便于连续阅读；
3. 阶段切换和文章大章节保留明确留白，形成停顿，但不制造半屏以上的空区。

页面不做成拥挤的后台表格。路线总览仍保留蓝色、金色、纸张底色和编辑式排版，但视觉
强调来自比例、对齐和字体层级，而不是大片卡片、夸张字号或无内容留白。

## 目录职责

```text
music-ai-lab/
├── roadmap/
│   ├── README.md
│   ├── roadmap.json
│   └── artifacts.json
├── learning/
├── notebooks/
├── projects/
├── docs/
├── tests/
└── site/
```

- `roadmap/roadmap.json` 保存 52 周路线、阶段、能力域和延伸方向。
- `roadmap/artifacts.json` 保存路线与实际学习产物之间的显式关联，供人和 AI 直接阅读。
- `docs/`、`learning/`、`projects/`、`tests/` 和 `notebooks/` 保存内容原文。
- `site/` 不提交任何内容副本；构建时产生的 `site/.generated/` 继续被 Git 忽略。

## 学习产物模型

网站不把单个源码文件当成一级内容。`artifacts.json` 中的每条记录表示一个有意义的学习
产物，例如一篇周记、一个环境练习、一个训练练习或一个 Notebook 实验。

笔记产物包含：

- 稳定 `id`、标题和简短说明；
- 一个 Markdown 路径；
- 关联的一个或多个 roadmap 周次；
- 可选的能力域 ID。

代码产物包含：

- 稳定 `id`、标题和简短说明；
- 一个练习或项目目录；
- 目录内明确列出的说明、入口源码和测试文件及其角色；
- 关联的一个或多个 roadmap 周次与能力域。

Notebook 产物使用同样的关联字段，并指向一个 `.ipynb`。同一产物可以关联多个周次，
不根据文件名猜测课程周次。

初始关联为：

- “环境与可复现性检查”代码产物关联 W01；
- “二维 PyTorch 训练闭环”代码产物关联 W02；
- `2026-W34` 周记只关联实际完成证据所在的 W01，不按正文关键词推断 W02 或 W04；
- 当前没有真实 Notebook，不创建示例内容。

构建脚本验证所有关联路径、周次和能力域。除集合说明文件外，允许展示的笔记、Python
文件和 Notebook 必须属于至少一个学习产物；出现孤立文件或失效关联时构建失败。这样
roadmap 关联不会随着仓库增长而悄悄失真。

## 页面结构

### Roadmap 首页 `/`

首页直接呈现 roadmap，不再先放四张入口卡。

首屏由紧凑的年度标题、当前路线说明、阶段跳转和总体进度结构组成。它保留明确品牌感，
但不使用占据大半屏的 hero、倾斜装饰卡或重复统计。

主体是连续的阶段与周次大纲：

- 阶段标题形成清晰章节，不独占一整屏；
- 每周默认显示周次、标题、目标、预计时间和学习产物摘要；
- 展开后显示学习内容、练习、交付物、验收标准与相关学习产物；
- 产物按“笔记”“练习”“Notebook”分组，但只展示当前周关联内容；
- 没有关联产物的未来周次保持路线信息，不展示空卡片。

现有内容视图、阶段筛选和周次展开能力保留，但改为扁平、连续、可扫描的版式。能力域
使用紧凑目录或索引呈现，不再使用六张大面积内容卡。

`/roadmap` 保留为兼容入口，指向同一个 roadmap 体验。

### 学习产物详情

Roadmap 中的产物统一进入 `/artifacts/[id]`：

- 笔记产物在该页面直接呈现 Markdown 正文和目录；
- 代码产物呈现练习说明、文件角色和该产物自己的紧凑文件目录；
- Notebook 产物直接呈现 Notebook 单元与安全输出。

现有直接详情路由继续存在，但只作为兼容地址：

- 笔记：`/notes/[...path]`
- 源码：`/code/[...path]`
- Notebook：`/notebooks/[...path]`

`/notes`、`/code` 和 `/notebooks` 不再提供全仓库列表；它们返回 roadmap 首页或明确引导
用户从 roadmap 进入。

每个详情页顶部使用小型面包屑显示“Roadmap / Wxx / 产物名称”，并提供返回对应周次的
链接。关联多个周次时全部列出，但不做成醒目的标签墙。

### 代码产物

点击 roadmap 中的代码产物先看到练习说明和一个紧凑文件目录，而不是全仓库源码列表。
目录只包含该产物声明的入口、辅助和测试文件。在目录中切换文件时保留当前产物页面、
文件目录和路线语境；每个文件使用 `/code/[...path]` 独立静态地址，代码详情继续复用
产物目录，而不是退化成孤立源码页。源码保留行号和语法高亮，宽代码区域可以比文章
正文更宽。

## 阅读排版

### 文章

- 笔记详情在宽屏使用正文与右侧目录组成的双栏阅读布局。目录从 Markdown 二级至四级
  标题生成，在距离视口顶部约 `96px` 的位置 sticky，并随滚动高亮当前章节；长目录
  在同一滚动帧将当前章节带到目录可视区中部。它使用普通文本和细分隔线，不做成
  抢眼的大卡片。
- 侧边目录不压缩正文行长：页面为目录预留独立栏位，正文仍保持约 `720–780px`。
- 当视口不足以同时容纳正文和约 `220px` 的目录栏时，目录移到文章开头的可展开
  “本文目录”中，不继续挤压正文，也不使用遮挡正文的悬浮面板。
- 桌面端正文栏宽约 `720–780px`，正文约 `17px`，行高约 `1.60–1.65`。
- 文章标题使用约 `40–56px` 的响应式范围，不超过正常首屏的一半。
- 页面顶部从导航到标题保持约 `56–80px` 的有效留白，而不是 `130px` 以上的空区。
- 一级章节间距约 `48–64px`；无论源码是否在标题前使用 `---`，标题外边距保持一致，
  紧邻标题的横线与标题分隔线合并为一条；段落、列表和代码块使用较小但稳定的垂直节奏。
- 标题、正文、带明确项目符号的列表、引用、表格和代码各自有清楚层级，不用统一套卡片。
- 块级和行内 LaTeX 使用 KaTeX 呈现；宽公式允许横向滚动，不显示原始 `$` 标记。

### 代码

所有源码和 Markdown fenced code block 使用 Shiki 生成的语法高亮。等宽字体使用明确的
跨平台栈：`ui-monospace`、`Cascadia Mono`、`Cascadia Code`、`Consolas`、
`Liberation Mono`、`Menlo`、`monospace`，不依赖下载字体变量。

代码块具备：

- 明确语言高亮；
- 稳定的等宽字体和 `tab-size`；
- 合理的 `14–15px` 字号与行距；
- 横向滚动而不挤压或换行源码；
- 克制的背景、边框和内边距，不用厚重阴影抢占注意力。

Markdown 的 inline code 与 fenced code 使用不同样式。未知语言回退为安全的纯文本高亮，
不执行原始 HTML。

### 响应式

窄屏下按阅读顺序自然堆叠：阶段、周次目标、路线详情、学习产物。正文保持舒适边距，
源码独立横向滚动。不能为了“紧凑”缩小正文或把多列内容硬塞进手机宽度。

## 导航

站点页头只保留品牌和必要的当前上下文，不再为唯一的 Roadmap 保留多余 tab，也不显示
“首页 / 路线 / 笔记 / 代码 / Notebook”五个同级入口。详情页通过面包屑说明所属周次，
并能一步返回路线。长文滚动时页头保持可见，并在视口右下提供返回顶部按钮。

## 构建与安全

- 构建期索引继续只扫描白名单目录，不在 Worker 运行时读取仓库文件系统。
- Vinext 使用 `output: 'export'`，在构建期为 roadmap、学习产物和每个内容详情生成 HTML
  与 RSC 静态文件。托管 Worker 只负责静态文件分发和 Vinext 客户端导航协议，不在请求
  到达时重新解析 Markdown、源码或 Notebook。
- `artifacts.json` 中的路径必须落在允许目录并存在于索引中。
- 路线 JSON 和关联 JSON 结构错误时构建失败，并报告具体产物或路径。
- Markdown 仓库内链接继续重写为安全详情 URL；未知路径显示为不可点击文本。
- 不执行 Markdown HTML、Notebook HTML/JavaScript、Python 或 Notebook 内核。
- 不新增数据库、登录、搜索、标签、收藏、GitHub API 或在线编辑器。

## 测试与验收

实现至少覆盖：

- 每条学习产物的周次、能力域和文件路径校验；
- 可展示内容的孤立文件检测与集合说明文件排除；
- 同一产物关联多个周次；
- roadmap 周次展开后只显示本周关联产物；
- 代码产物按目录分组，不产生全仓库文件列表；
- Markdown fenced code block 的等宽字体、Shiki 高亮和安全转义；
- 笔记目录从二级至四级标题生成，桌面端跟随阅读位置并自动滚动，窄屏可以展开和收起；
- Markdown 数学公式由 KaTeX 呈现，列表符号和四级标题清晰可辨；
- sticky 页头和返回顶部按钮在长文滚动后可用；
- 笔记、源码与 Notebook 详情的 roadmap 返回上下文；
- 代表性路由均生成静态 HTML，笔记、练习和代码文件之间的客户端导航不替换浏览器文档；
- 未知路径 404、损坏 Notebook、安全输出和空 Notebook 状态；
- 桌面和窄屏真实截图检查，确认没有巨型空白、内容挤压、字体回退或横向溢出。

完成时运行站点测试、roadmap 数据校验、TypeScript、ESLint、生产构建和 Python 回归测试。
验收还需由浏览器实际查看至少一个 roadmap 周次、现有周记和现有 Python 源码；只检查
HTTP 状态码不算视觉验收。
